rows are not additional games. Every comparison swaps map sides.

PRODUCTION CHANGE

Only capture_handoff is retained in bots/study28/src/main.cpp. A living ally
that still claims a camp but is channeling off its capture mask cannot win
the capturer election. The available ally continues the capture instead of
abandoning it for 12 rounds. On-mask capture/recall overlap is preserved.
This is a three-line insertion. Draft, item plans and parameter values do
not change. All other source files are byte-identical to the baseline.

channel: cancel then escape immediately instead of restarting the channel.
dash: ready dash + ordinary move + melee attack envelope, including volley.
danger: remember full local epoch so an unchanged5-bit packet cannot revive.
capture_income: verify group respawning before interpreting personal income.
capture_handoff: exclude off-mask channeling allies from capture delegation.
ally_lock: conservatively protect possible allied tributes at a candidate altar.
spawn_path: include altar obstacles in the spawn distance field.

WHAT WAS EXCLUDED

The two channel implementations and spawn distance change were negative in
their isolated development results. Dash was near neutral; adding it to
handoff reduced the gain. Capture-income was neutral. Danger and ally-lock
had small positive point estimates but inconclusive direct incremental
evidence. They remain inspectable, independent patch functions under
tools/study28_fixes and are not enabled in the production bot.

Focused regressions exercised actual inserted C++ helper/blocks with stand-in
SDK state:17 combat checks, 21 alternative-channel checks, 1002 danger cases,
21 income states, 24 handoff cases, 12 lock fixtures and 4 utility/source checks.
Composition ordering, baseline preservation and additional 226 danger overwrite
cases were checked. The full bot variants were then built and played above.
The portable bench tool was independently reviewed; it reconstructs the
original from local Git history and performs no online submission.

REPRODUCING

Run cambc init --yes once in a Git clone. Ensure the baseline commit exists.
python tools/study28_fixes/bench.py --candidate handoff-dev --features capture_handoff --maps "maps/*.map26a" "maps_gen/*.map26a" "maps_dev200/*.map26a"

Repeat with --features channel,dash,etc (comma-separated for combinations).
channel and channel_resume are mutually exclusive. Use a new candidate name
for each feature set. --prepare-only creates checked copies without games.

To replay the disclosed confirmation cohort:
python -m zipfile -e analysis/study28-fixes/confirmation-maps.zip out/study28-confirmation
python tools/study28_fixes/bench.py --candidate handoff-confirm --features capture_handoff --maps "out/study28-confirmation/*.map26a"

Default jobs=1 avoids Windows metadata races; set CAMBC_CLI to the executable
if needed. Replaying deterministic inputs is reproduction, not new evidence.
The neighboring experiments.json.gz stores every unique outcome, exact input
hashes and stage membership; validation.json pins the audit and frozen source.
Full per-game statistics and selected replay bundles were retained locally.
