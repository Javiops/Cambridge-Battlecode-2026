# First tactics bot: reviewer checklist and limits

This is a new bounded architecture with declared strategic gaps. The implementation audit records source presence and scoped test evidence; it does not mark any of the 96 topics fully verified or establish competitive strength.

1. **Match the artifact.** Compare all production source hashes, the official SDK pin and the played release-module hash with the final execution report. A scripted fixture has its own module; an earlier repaired game is development evidence.
2. **Check the decision boundary.** A feasible winning bank precedes ordinary work; a blocked/lethal first altar does not hide the second shortlisted route. A safe faster geodesic walk may replace recall, while disconnected walking must not veto recall.
3. **Check legal state transitions.** Dead actors, a first personally visible enemy, accepted movement before an exclusive cast, shared cast budget, ranged movement/reset, transformed lock hits and rejected actions must use actual SDK outcomes. The gateway rechecks the epoch and 12000 actual fuel after legality queries before mutation; dash path work separately requires 24000. The range mask alone is insufficient for a dash: current units, camps and teleport reservations can block the only intermediate path. New input epochs must not execute an old decision. The bulk-record adapter uses official imported SDK 2.2.2 types and host visibility checks; review it against a newly pinned header before upgrading the SDK.
4. **Check capture and channels separately.** A real last holder remains until payout or supported overlap/handoff. Accepted recall/tribute is only a start; pending zero, actual interruption, departure, capture payout and scoreboard conversion are different observations.
5. **Inspect the native execution evidence.** Count native faults, caught errors and `fuelExhausted` separately, and inspect whether useful actions actually occur. Earlier versions had real fuel pauses. Source guards and passing pure helpers cannot certify the final module's runtime budget.
6. **Review the declared limits before expanding the strategy.** Preserve known-safe fallbacks and add an observable acceptance case for each new shared protocol or optimizer.

## Explicit first-version limitations

- **04.8, information sharing:** local public observations and objective claims exist; fresh strategic danger sharing with a richer reader/writer protocol is absent.
- **05.6, route loops:** camp-clear stagnation and rejected moves are bounded; a general task-progress/A-B-A movement loop guard is absent.
- **06.2, group versus split:** the smallest sufficient visible ready crew is modeled; accepted team assignments and each helper's marginal alternative are not implemented.
- **09.7, territory:** safe local resource cycles exist; explicit territory, denial and invasion mission planning remains partial.
- Ward placement is a four-anchor personal-observer prototype admitted on idle/hold opportunities with sufficient fuel. It does not implement full proactive scouting or opportunistic placement before every useful movement/action.
- Recent missing enemies remain risk hypotheses, never legal stale targets. Large or costly uncertainty sets use conservative geometry, which can retain danger through walls or despite unexamined visible absence and make farming/recall too cautious.
- Crew affordability charges each observed camp to the nearest selected body and charges every distance tie fully. It checks each selected body's current health rather than dividing damage by a nearby headcount; hidden camp members conservatively charge self. This is a coarse current-position full-clear model, with no future tank rotation or accepted team commitment. A separate conservative immediate `farm_safe` guard can reject some tanked cooperation; monolith-only attrition can proceed under its explicit shorter safety fallback without whole-clear affordability.
- Local resource ETA, arrival and risk estimates remain coarse. The native cycle fixture covers normal recall on a single capture tile and later tribute completion; it does not establish the full arbiter's activation, Home/contest behavior, or large multi-body-map runtime performance.
- Draft, shopping, heal thresholds, local assembly, short combat sequences and return-cycle valuation use documented coarse recipes or bounds. There is no exact team fight simulator, full counterdraft, globally optimized formation, private enemy-state knowledge or fully priced elective recovery model.
- Geometry and reachable objectives replace map-name strategy branches. Passing a small map set does not prove adaptation to all unseen tournament geometries, and no ladder-strength or optimal-threshold claim follows from these correctness tests.

The four numbered gaps are recorded as **PARTIAL** in the audit. Other topics distinguish a concrete bounded implementation from an explicitly permitted narrower fallback or optional omission.
