# October 20 runtime migration

This project targets Cambridge Battlecode Autumn 2026, CLI/SDK **3.0.1**. The official
[patch notes](https://2026a.battlecode.co.uk/game/patch-notes/2e172875-28d7-4152-9483-54a3db6d2663)
change champion and camp designs as well as the SDK's dash metadata. Rebuild source against
the current SDK before evaluating it.

The observed release engine build is
`2b36d9c61b2710d06036680d07fc4b7a8319ba35f634e4f1445725e0d99a1e16`.
The engine reports version `1.0.0`, so that version alone cannot identify this patch.
`lab.toml` pins both the CLI and build hash. Frozen metadata records the actual SDK fingerprint;
every completed match must report the pinned engine hash.

## Migration

1. Install `requirements-lab.txt` in this project's environment and run `cambc init --yes .`.
2. Run the unit tests and `python3 -m lab probe`. The probe builds and runs release WASM and
   requires a completed match, complete safety statistics and all expected design rows.
3. Freeze the three reference sources under the new `*-week2-v1` names listed in README.
   Preserve old `archive/` versions and game files. Old binaries cannot enter the current league.
4. Run a fresh screening league. Panel version 3 separates it from the old calibration history.
   Ratings from before this patch do not establish the strength of a current bot.
5. Keep the new `01*` maps sealed for promotion gates. They have only been copied and hashed
   during this migration; no confirm games or replays were used to tune a candidate.

The current 21 map files are included. `mechanics/maps-2026-10-20.json` records their byte hashes.
Refreshing maps later can change the experiment; review the map diff and repeat calibration.
An engine update similarly requires a new pin, new frozen version names and a panel-version bump.

## Judge changes

- Unknown outcomes and incomplete captures fail. Full games resolve ties to a team, so truncated
  games are never converted into draws.
- A failed process cannot supply a valid result merely by leaving a stats file behind. Reusing
  a replay directory also discards its previous stats before running.
- Promotion requires the entire map schedule in both seats, a distinct opponent, and disjoint,
  nonempty map sets. Empty or entirely failed schedules produce a FAIL report.
- A reference serving as both champion and weak opponent is counted once at the stricter threshold.
- Cache keys and frozen metadata identify the runtime; old result records cannot silently reappear.

## Verified engine facts

`mechanics/constants.md` and `constants.json` were generated from a completed release game.
They include Heart of Ruin, Golem, all base stats and the expanded dash fields. Key changes include
ward cooldown 10, altar lock hits 5, kill gold 100, Prism Focus/gem 1, Vesper bonus gold 33%,
Marcella tribute gold/gem 2, Tavi Strength 45 and CC multiplier 1.4.

The SDK exposes base camp designs, but its design ABI does not provide reward or respawn fields.
Use the official patch notes for those values. The diagnostic probe can spend several turns printing
its designs; it is not an inference fuel benchmark.

## Validation on the real checkout

All **40 tests pass**, including the original private collision fixture. The fresh three-reference
league completed **99 release games on 11 screening maps**, with **zero bot faults and zero fuel
exhaustion**. End-to-end league and report generation took **23.679 seconds with four workers**
(4.181 completed games/second on this machine). See
[the calibration report](results/calibration-2026-10-20.md) and
[machine-readable validation](results/patch-validation-2026-10-20.json).

The seed control differs from starter by 94 rating points and wins 64% head-to-head over 22 games;
their bootstrap intervals overlap. This small map pool cannot establish small improvements.
The reference source bundle also rebuilt to exactly the frozen release WASM hash.
No confirm games were run and no candidate was promoted.

## Seven-stage work

This migration supplies part of stage 1's measurement loop; **stage 1 remains open**. The official
runner is the verified oracle. Reference calibration and initial end-to-end throughput measurement
are complete. Before collecting the stage 2 dataset, decide how the training environment will step
and batch games, validate any custom fast simulator against the official engine, and run a tiny
C++/WASM inference fuel test. Broader map generation and handicap controls also remain on the roadmap.
The later stages remain: behavioural cloning, outcome critic, self-play PPO, production
C++ inference integration, then final strong-opponent qualification. Evaluate the exported artifact
throughout the work and reserve final confirm maps/opponents for qualification.
